Engagement app Design System

Design system for Linus, a consumer app for taking mental-sharpness assessments — calm, encouraging, and human, never clinical. This page is the human-readable mirror of docs/design.md, the source of truth a coding agent implements from. Every token renders with its real value.

Border

A four-tier gray scale plus three functional variants, all direct aliases — border/border-strong used to be independent, unaliased values; they're now fully consolidated onto the primitive. border-subtle and border sit under the 3:1 non-text-contrast minimum (decorative-only, or paired with another cue like shadow/padding); border-strong is the one tier that clears 3:1, for when a border is the sole indicator of a boundary (a resting input outline on a white surface). border-disabled shares border-subtle's value under a distinct name; border-danger/-success/-info each alias the same primitive step (danger-500/success-500/info-500) their matching semantic token does.

Typography

Two families: IBM Plex Sans for body/label/button text, and Plus Jakarta Sans as the accent face for every Headline style (headline-1 through headline-5) — a deliberate accent for titles, not a wholesale typeface swap. Headline's accent treatment was initially scoped to just headline-1–headline-3, the three largest sizes, before being extended to all five Headline steps for a consistent title voice throughout. Every Paragraph/Label/button style stays on IBM Plex Sans. A 1.200 (minor third) modular scale, base = paragraph-2 = 16px, with one deliberate exception (headline-5, added later for a real need — see below). 12 sizes × 2 weights = 24 tokens, plus a dedicated button style outside the scale. No Display category and no Bold (700) weight remain — both were removed after the scale was first built. Note the naming direction flips between categories: Headline counts down from largest (headline-1 biggest), Paragraph counts up from smallest (paragraph-1 smallest).

Breakpoints

New to this doc, not new to the codebase — src/tokens/spacing.ts has exported this exact mobile/tablet/desktop object since the src/ reconciliation session; it was simply never documented here. Min-width, mobile-first: a tablet-qualified rule applies from 768px up, superseding the unqualified rule below it, and so on upward. This reference page's own chrome (the sidebar collapses at 860px, the color swatch grid drops to 2 columns at 640px) predates this scale and intentionally keeps its own values — those are the page's own authoring breakpoints, not a rendering of the product scale below.

mobile · 0px and up · the default, no media query needed
tablet · 768px and up · @media (min-width: 768px)
desktop · 1280px and up · @media (min-width: 1280px)

Motion

New — durations and eases, previously only ever inlined ad hoc per component with no shared vocabulary. Every transition already in this system now points at one of these tokens instead of a scattered magic number; hover the buttons and toggle on other pages and the timing you feel is one of these three durations.

Duration

duration-fast120ms · a color swap, nothing moves
duration-base150ms · something travels a short distance
duration-slow250ms · a large surface enters/leaves
See Modal →

Easing

easing-standard (cubic-bezier(0.4, 0, 0.2, 1)) for most transitions; easing-enter (cubic-bezier(0, 0, 0.2, 1), decelerate) for something arriving; easing-exit (cubic-bezier(0.4, 0, 1, 1), accelerate) for something leaving. Modal is the first component to use the direction-specific pair.

Layering

New — a z-index scale, ordered so a toast can never end up trapped behind an open modal, and a tooltip — transient, contextual, triggerable from inside anything else including a modal — always wins. Spaced by 100 to leave room to insert something later without renumbering. overlay-backdrop and modal back Modal below, the first real consumers; the rest are reserved ahead of the components that will need them (see the Deferred proposals in the session notes) rather than left to be improvised later.

dropdown · 1000 · reserved, no consumer yet
sticky · 1100 · reserved, no consumer yet
overlay-backdrop · 1200 · backs Modal's ::backdrop
modal · 1300 · backs Modal's panel
toast · 1400 · reserved — must outrank an open modal
tooltip · 1500 · reserved — must always win

Icons

This system's first documented icon set. Sourced from Phosphor Icons (MIT-licensed, open source) — real SVG markup pulled directly from phosphor-icons/core, not redrawn. Regular weight specifically (24×24 grid, stroke="currentColor") so every icon inherits whatever color its container already sets — the same recoloring this system's iconColor tokens already rely on elsewhere (Search's icon, Tag's remove ×, Modal's close button). Deliberately a starter set, not the full ~1,500-icon library: these 12 were added on request; more only as a real component actually needs one. No new size or color tokens — recolor via the existing text/content tokens on a wrapping element, size via plain CSS on the <svg>. clock, arrow-right, play, check-circle, sign-out, and user also have real React implementations (Icon/ClockIcon, Icon/ArrowRightIcon, Icon/PlayIcon, Icon/CheckCircleIcon, Icon/SignOutIcon, Icon/UserIcon) rather than existing only in this reference page.

Buttons

5 variants (primary/secondary/tertiary/danger/outline) × 3 sizes (lg/md/sm) × 5 states (enabled/hover/pressed/disabled/focus). button-primary is a solid pill using primary-hover (changed on request from primary-strong, which read almost black — see Semantic Colors), stepping to primary-pressed on hover/press; button-secondary is a blue outline pill (changed on request from a solid secondary-subtle fill) — border and text always match, stepping through primary/primary-hover/primary-pressed, the same ramp button-primary itself uses; now visually close to button-outline below, distinguished only by color; button-tertiary is text-only, no fill or border; button-danger shipped to src/components/atoms/Button in a later session for real destructive actions and was documented here well after — it reuses danger/on-danger exactly, darkening on hover/press via a brightness filter rather than a new color. button-outline, documented here for the first time, is older than the primary/secondary naming itself and was never migrated to either — it's still real, still shipped (Onboarding/Dashboard "Back", Device Setup "Exit"), so it's captured here as a genuine 5th variant rather than forced to change: a bordered surface-fill, text-primary-text style, every token already existing. Every color here is a semantic token, nothing invented. Focus rings are also corrected below — the previous single-layer soft-tint ring measured ~1.1:1 against a white surface, under the 3:1 a focus indicator needs; it's now a surface gap plus a solid contrast-passing ring.

Progress Bar

A plain track + fill — border for the track, primary for the fill, the same 8px height as the segmented progress-stepper on the Question Card page but with a flat 0 corner radius rather than rounded.pill — the one deliberate exception to this system's "no sharp 0px corner" rule; progress-stepper itself is untouched. A success-filled variant marks a completed state, and the fill animates its width on change with motion.duration-base + motion.easing-standard rather than jumping straight to the new value. Wherever this is actually implemented, the track needs role="progressbar" plus aria-valuenow/aria-valuemin/aria-valuemax (added below) — a plain unlabeled <div> conveys a filled bar visually but nothing at all to assistive tech.

Modal

New — the highest-value gap this audit found: alpha.scrim-48, elevation.shadow-modal, and rounded.xl were all already defined (the Shapes section of docs/design.md already named rounded.xl for "modals, the score card") but nothing ever consumed them. Built on the native <dialog> element — focus trapping, Escape-to-close, and an inert background come from the platform, consistent with this system's preference for real native elements over custom-built equivalents. Panel entry/exit uses motion.duration-slow and motion.easing-enter/-exit, the first real consumer of Motion above.
